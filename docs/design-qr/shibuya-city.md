# Shibuya city design

[Back to the Design QR documentation index](README.md)

The first `city` design is a QR-driven Shibuya miniature that turns into a
scannable QR. It shares the existing player's camera, transition speed control, pointer
and keyboard interaction, logo, presentation surface, and PNG export.

## Reference interpretation

The supplied JPG shows blue-hour Shibuya from above: dense stepped buildings,
large illuminated screens, warm shop fronts, a diagonal scramble crossing, and
an elevated railway. The supplied MP4 shows alternating pedestrian and vehicle
phases and trains. These inform the modeled composition and motion; the city
is stylized. The later road references (`Shibuya-road.png`, `Shibuya-road-1.png`,
and `Shibuya_1080p.mp4`) prompted a geographically grounded road replacement:
the shared foundation now derives from official PLATEAU carriageway/sidewalk
coordinates, with marking placement checked against georeferenced GSI imagery.
The later station-side building references add PLATEAU-derived building contours,
QFRONT/MAGNET heights and a separate police box / Hachiko entrance frontage. Façades, station
structures and activity remain illustrative, not an as-built city digital twin.
See the [building research and accuracy limits](shibuya-architecture.md).
Reference photographs, video, and stock watermarks are not distributed.

The `plan/dog/` references add the seated Hachikō statue and its planted square.
The monument sits at the western side of the plaza, south of the scramble,
facing geographic east toward the station. Its Blender-authored sculpture, inscribed pedestal, garden beds, trees, lanterns
and seating complete the square. The reference garden setting predates redevelopment work reported
in March 2025; it is not a current construction snapshot. See the
[Hachikō research, scale and geometry contract](hachiko-square.md).

The supplied Blue Period image and proposed three blue swatches now guide
**青の朝**, a soft morning palette with distinct glazing, concrete and road
roles. Existing gold and coral remain small signs of city activity. The complete
[color roles](color-palettes.md#shibuya-city--blue-morning) define all base colors
and blends. The original Osaka swatches remain only in the validated GLB
source materials; per-player semantic mapping applies the morning colors.

Sign composition also references [GO TOKYO's Shibuya street photographs](https://www.gotokyo.org/en/story/walks-and-tours/shibuya/index.html)
and [SHIBUYA109's official screen and facade media](https://shibuya109square.com/service/109%E3%83%95%E3%82%A9%E3%83%BC%E3%83%A9%E3%83%A0%E3%83%93%E3%82%B8%E3%83%A7%E3%83%B3/):
large crossing screens contrast with stacked tenant panels and vertical shop
signs. The runtime paints original artwork; it includes no copied advertisements.

The settled 2D QR keeps exact deep-blue `#29445F` finders and combines four
data-cell inks in stable facade-sized groups: deep blue, morning blue, slate
blue and sparse warm gray. Light cells use a pale mist/white blend. Each cell
has one flat opaque color, bypassing Tree's brightness lift and scene shading.
Only enabling Border fills the four-module margin and details card. Border off
keeps the paper within the matrix, with atmosphere or transparent host visible
outside. This applies to the editor,
React/iframe players and PNG export. Original QR modules and the existing
bounded high-error-correction Logo mode remain authoritative.

## API and implementation

- `design="city"` selects the city adapter; `theme="shibuya"` is its default.
- The QR matrix determines contextual architecture and details. Canonical City
  configuration uses `design: { type: 'city' }`.
- The editor's Tree / City selector changes the design without changing the
  value, logo, view, or interaction settings. The next row shows Shibuya as a
  selected preset button, just as Tree initially selects Spring. It is City's
  only preset for now; reselecting it with pointer, Enter, or Space preserves
  the current artwork and shared settings. Custom seasonal theme controls
  belong to Tree, and choosing Shibuya never overwrites the remembered Tree theme.
- City currently accepts only the Shibuya preset. Canonical configuration and
  the public player reject custom or seasonal City themes with `INVALID_CONFIG`.
  Add Theme, saved custom themes, and the Share dialog's Custom Theme React
  example are available only for Tree. Switching back to Tree restores its
  selected preset or custom theme. City Simple snippets include `design="city"`;
  Advanced snippets preserve the current view, and shared options.
  Switching to City closes an open Tree theme editor and cancels its unsaved
  preview, retaining the previously selected Tree theme.
- The QR matrix is generated by the existing encoder, with high error
  correction when a logo is present. City construction copies the complete
  matrix without carving roads or buildings into it.
  Both designs keep the shared 57×57 interactive matrix limit. Oversized content
  shows an error without a stale canvas; editor Share and Download remain
  disabled until the content is valid.
- Both dark and light QR modules have city-derived morph tiles. Building volumes,
  geographic road/paint/pavement, signs, station/street/garden details, and visible
  actors join the transition. Tiles descend and move to nearby exact QR targets;
  completed scan output contains no decoration. See the whole-city contract below.
- Merged contour-following meshes batch building façades and windows; instanced
  boxes batch street furniture. One merged,
  palette-colored mesh contains the surveyed road, curbs, and clipped markings.
  Instanced pedestrians and vehicles animate while the design view is settled.
  Resource disposal covers geometry, materials, textures, and instance buffers.
- Existing `TreeData` is retained internally as the player transport shape; its
  optional city payload bypasses tree construction and the tree render loop.
  Shared `ResolvedTreeTheme` roles continue to feed the common presentation API.

## Whole-city morph

The transition preserves the shared approximately 0.56-second 1× duration and
camera/logo motion. Building blocks reveal progressively in upper-to-lower
sections over 8–42% of eased progress, with a small stable offset between
buildings. Each section blends over a 24–26 percentage-point window rather than
switching the entire skyline over 30–42%. Source volumes, silhouettes and
destinations are unchanged; grouped travel still starts at 42%. Detailed city
geometry stays opaque through 40%; streets and other details keep their 30–42%
tile reveal, before the original geometry retires over 40–46%. This
coverage-first overlap avoids the former whole-city see-through phase.
Original glass retains its own base transparency.
Both dark and light tiles retain their city colors initially, then acquire their
exact scan colors between 50% and 94%.
The canonical QR and paper plate cover the tile layer between 94% and 100%,
with opaque tiles retained underneath until that handoff is complete,
preserving the original scan/export pixels. The presentation surface's existing
final-18% card/matrix fill and Border-owned quiet zone are unchanged.

- Each encoded cell receives a base tile. Exposed road and paint supply dark
  cells as well as light ones; pavement supplies light areas. Light destinations
  underneath buildings or stair wells use the nearest exposed ground instead.
  The remaining dark cells use blocks packed inside the generated buildings.
  Bounded local matching shortens crossing paths within each building without
  changing parcel ownership or any encoded cell.
- Signs, station surfaces, street furniture, garden/Hachikō and trees contribute
  additional small fragments. Each visible commuter and visible vehicle/train
  body segment starts from its actual current transform. Limbs/wheels merge with
  their body. Each car, the connected metro, and both halves of a sign panel
  retain a common translation, heading and footprint before their individual
  cells resolve. Neighboring crowd/station/garden fragments also move in local
  groups. Crossings add at most twelve evenly distributed thin strips each,
  contained in the actual zebra paint, with asphalt tiles underneath. Their
  stripe proportions and orientation persist longer than building blocks.
  Destination occupancy is bounded per ink, normally to two extra fragments
  per cell; distinct cells within an object are preferred. This is visual
  correspondence, not a change to QR encoding or one QR cell for every mesh part.
- Source colors come from the existing palette, sampled static vertex colors,
  and semantic sign/vehicle paint. No new texture, authored color, lighting pass,
  model download or scene-resolution increase is introduced.
- QFRONT's vision panel and MAGNET's corner/side posters retain their actual
  artwork on six folding half-panels. The full physical panel and its original
  left/right UV ranges are preserved. Rigid folding and uniform shrinking keep
  glyph proportions intact while the halves follow their existing grouped
  destinations. Artwork covers the transition over 30–42%, then dissolves into
  the underlying palette-colored tiles over 58–78%; none survives on the final
  scan face. All other signs retain their bounded two-color fragment treatment.
  These faces borrow the live sign maps, not snapshots or an atlas. In Logo
  mode, QFRONT's borrowed map contains only the cleared sign background/ticker;
  the single uploaded image keeps its existing independent journey to the QR
  center, original colors, transparency, proportions and size limits. Replacement
  or removal repaints the private hero map in place, including while paused
  mid-turn; no uploaded logo enters the fragment layer.
- Ground samples are cached per QR size; bounded, deterministic static surface samples
  are collected lazily. Actor transforms are captured once when leaving 3D and
  reused through reverse turns and content edits. Only returning to live 3D
  releases that snapshot; the original simulation objects and clock persist.
- Ground sampling visits only cell centers inside each polygon's bounds, with
  the same exact contour/hole tests and color calculations as before. Hidden
  light-cell sources use a distance-bounded grid search with stable row-order
  ties instead of scanning every exposed cell. Building/ground correspondence
  is cached per content revision, so repeat turns only rematch moving details.
  The first requested turn starts compilation of the existing tile shader and
  flushes its commands without waiting for completion. Sign faces reuse the
  already compiled sign shader. There is no speculative mount-time preparation,
  hidden render, shader-ready polling, or deferred task retaining a disposed
  player. Driver compilation can still stall on its first use; this is not a
  real-device frame-rate guarantee.
- One transient instanced batch carries at most one base tile per matrix cell
  plus 512 detail fragments (under 3,800 instances at the 57×57 limit). Movement,
  rotation, size and color interpolate on the GPU. A frame changes uniforms,
  not instance buffers. The batch is hidden and receives no animation updates
  in settled 3D or QR; its capacity is reused across turns and content edits.
  Reduced motion commits directly without creating a transition batch.
  Building reveal windows add two floats per instance, uploaded only with the
  correspondence. The same draw starts earlier during the turn; no new mesh,
  material, texture, pass or mount-time work is introduced. The vertex shader
  evaluates each window; zero-opacity fragments discard before writing depth,
  so unrevealed streets/details cannot occlude the emerging building sections.
- The retained sign artwork adds one small merged geometry and at most three
  ordinary single-pass material groups only while visible. Its six quads update
  36 positions (432 bytes) per changed visible frame; UVs, normals and texture
  maps are unchanged. This bounded exception avoids a new sign shader variant.
  The main tile batch remains GPU-animated with no per-frame attribute uploads.
  Neither transient layer adds a draw or position upload at settled endpoints.
- Group translation runs over 42–90% of progress; individual cell resolution
  starts at 54% for buildings/local details, 58% for signs, 60% for cars/metro,
  and 62% for crossing paint, completing at 94%. Height collapse remains
  continuous throughout. There is no added delay or change to the shared speed.
  Destination lookup searches nearby grid rings and stops when farther cells
  cannot improve the score, avoiding full-grid scans in typical city layouts.

The implementation lives in [morph.ts](../../packages/designqr/src/designs/city/morph.ts),
[morph-sources.ts](../../packages/designqr/src/designs/city/morph-sources.ts),
[morph-correspondence.ts](../../packages/designqr/src/designs/city/morph-correspondence.ts),
[morph-mesh.ts](../../packages/designqr/src/designs/city/morph-mesh.ts),
[morph-signs.ts](../../packages/designqr/src/designs/city/morph-signs.ts), and
[ShibuyaScene.ts](../../packages/designqr/src/renderer/webgl/ShibuyaScene.ts).
`npm run smoke:shibuya-morph` checks forward/reverse captures including the
progressive building reveal and short final handoff, opaque coverage, object groups, bounded occupancy, all source
categories, unchanged actor poses and shader attributes during the turn,
stable endpoint pixels, decoded QR exports at desktop/mobile sizes, reduced
motion, bounded GPU resources and disposal. The content-continuity smoke test
continues to cover edits in both views and mid-turn.
The morph unit tests cover roof-to-base ordering, unchanged non-building timing,
opaque coverage and lower worst-case reveal jumps using the shared timing curve
at 30/60 fps, 1×/2×, both directions and different refresh offsets. These are
deterministic timing checks, not a device frame-rate guarantee.
`npm run smoke:shibuya-morph-detail` additionally checks retained panel UV/texture
ownership and shader reuse, logo replacements/removal during a paused turn,
wide/tall transparent images, repeat-turn cache reuse, desktop/mobile captures,
exact endpoint PNGs, QR decoding and disposal. Its report separates CPU
preparation, shader kick-off and render-submission timing; those measurements
are not GPU completion times or physical-phone FPS. Set
`DESIGNQR_MORPH_PROFILE=1` for optional CPU profiles (profiling changes timing).
Shader preparation uses Three.js's
[targeted compile API](https://threejs.org/docs/pages/WebGLRenderer.html#compile)
and a non-blocking [WebGL flush](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/flush).

## 3D models

QFRONT, MAGNET by SHIBUYA109, the taxi/sedan/van/bus fleet, spinning wheels and
four-car metro use Blender-authored models. Their source-aligned building
contours also define the QR morph volumes. Roads, station details, the other
buildings, 180-person crowd and sign artwork are generated from the shared
geographic data and palette. Vehicles use instancing and world-space tile
clipping. The train has two outward-facing outer cabs on its east-side route.

Assets are packaged in lazy JavaScript chunks with embedded GLB bytes, so
consumers do not configure model URLs, copy public files, or install Blender
or compression decoders. Tree does not fetch the City model payload.
Hachikō's compact sculpture ships with the City implementation.
Each player owns its geometry, materials, clipping planes, signs and uploaded
logos. The existing camera, transition and exact QR destinations govern the
complete scene. Loading and resource ownership follow the asset contract below.

See [Blender asset authoring and verification](shibuya-blender-assets.md) for
editable source, semantic geometry contracts, regeneration, and package tests.

## Street-safe, content-driven architecture

`road-network.ts` owns the shared 160 m survey tile: the asymmetric five-arm
crossing, curved road edges, actual sidewalk polygons, five crossing axes,
and a geographic east-side railway reservation. `layout.ts` consumes fifteen
disjoint source-aligned building parcels generated against those reservations. Parcel
density must fit the land; never widen roads or invade pavement to retain an old
building count. QFRONT and MAGNET retain source heights of 45.9 m and 34.2 m;
context heights remain QR-dependent. Each building's complete envelope includes windows,
roof rims, equipment and billboard surfaces, not just its center
or structural walls. Dimensions and offsets are generated inside that envelope;
no subsequent random displacement can move a building into a street.
Polygon containment checks include intervening edges and holes, not only four
corners. See [road data, proportions, and limitations](shibuya-road-network.md).

A stable hash of every QR bit and matrix size drives contextual
glazing, roof and tenant details. Local QR dark-cell density and the hash
control quantized context heights. Different content therefore changes the
skyline even when its QR dimensions remain the same; the same matrix
reproduce the same architecture in the editor, React, shared links, and embeds.
QFRONT's glazed chamfered building and MAGNET's corner-poster building remain
recognizable landmarks; the cylindrical flagship 109 is outside the tile and is
not invented here. Source-aligned geographic footprints, roads, crosswalks,
railway and the QR-relative tile stay stable. Source hashes, interpretations
and reproduction steps are in the [architecture contract](shibuya-architecture.md).

The scene shares its generated building list with facade rendering,
pedestrian clearance, billboard/logo anchoring, and morph-voxel packing. A valid
content edit regenerates contextual architecture and morph destinations in the
existing scene. Unchanged geographic envelopes keep the existing pedestrian
plans safe; no new crowd planning is required. No city geometry changes the
encoded QR modules.

### Live content updates

For the same City design and theme, changing `value` preserves the people,
vehicles, wheel rotation, metro, signals and shared activity clock. These are
the same live objects, not replacements positioned at an approximate old time.
The fixed streets, station, subway entrances, Hachikō and imported landmark
models also stay attached. Only the contextual building mesh, changed sign
panels and QR/morph data are updated. Identical signs retain their textures;
unused sign maps and replaced geometry are disposed, and QR instance capacity
is reused until a larger matrix requires it to grow. There is no additional
animation loop, render buffer, asset request or per-frame simulation workload.

This holds for same-size and different-size QR content, during a turn, and in
the settled scan view. The existing QR-relative camera/scene scaling preserves
the ground footprint when matrix size changes. View, rotation, preview zoom/pan
and the configured logo remain intact. Paused updates redraw the new artwork
without advancing actors; reduced motion keeps its stable pose. Pending models
retain their original load token and attach only in a running settled frame.
Returning to 3D resumes the preserved simulation; it does not restart the
crossing or train loop.

The shared package renderer owns this behavior, so the editor, React `value`
updates and hosted-player configuration updates benefit without new props.
Explicit City design/theme changes and component remounts may rebuild the
simulation. Invalid/oversized content still replaces the player with its
existing error state; restoring valid content after that unmount starts a new
scene. Animation progress is transient and is not serialized into links or
exports.

## Default city animation

City activity starts automatically in the settled 3D view, independently of
automatic camera rotation; no animation option is required in React, embeds,
or shared links. The initial frame starts during a pedestrian phase.

- 180 commuters cross in both directions along the five shared zebra routes
  and an unmarked counter-diagonal connecting opposite corners. The two
  diagonals carry more people, creating intersecting flows through the center.
  Heads, coats, arms, and legs form small articulated figures with alternating
  steps and a subtle vertical gait. Deterministic departures, walking speeds, changes
  of pace and curved paths vary on the outward and return trips. Both directions
  share the crossing width. Walkers anticipate nearby encounters, sidestep
  around one another and turn around signal posts; their movement remains
  inside the crossing corridors.
  Arc-length travel keeps curved curb approaches from producing speed bursts,
  and accumulated distance drives each person's footsteps. Spaced waiting positions occupy clear sidewalk pockets,
  avoiding walls, trees, and one another. Commuters fan out after crossing, face
  toward the intersection at varied angles, and use relaxed arm poses. Foot
  height follows the road and raised pavement through a short curb ramp.
- A smaller group from the Hachiko, station-east and main diagonal crossings
  continues through the square into the JR Hachiko entrance beside the police
  box. Up to 18 of the existing commuters take this route, depending on clear
  approaches between the curb queues. They enter the recessed concourse, spend
  time behind its rear wall, and come out in a staggered flow toward the next
  available crossing. Arrival and departure paths fan through the plaza,
  yielding around other walkers while keeping the garden, furniture and subway
  pavilions clear. Foot height follows the station's raised floor. These longer
  journeys take 80 seconds; plaza walking continues while road traffic moves,
  with returning commuters waiting at the curb for their walk signal.
- A 20-second intersection cycle lets pedestrians cross and clear before cars
  begin reacting after 12 seconds. Pedestrian signals turn red during clearance.
  Drivers brake progressively into their queues, then pull away in a reaction
  wave with individual acceleration and following headways. Buses accelerate
  more gradually. Vehicles
  arrive from and leave beyond the tile edges rather than jumping across roads.
  The fleet includes sedans, roof-sign taxis, taller vans, and city buses, with
  distinct proportions, glazing, doors, mirrors, bumpers, lamps, and round
  wheels. Vehicles follow curved left-side lane paths with heading
  and arc-length wheel travel. Queue gaps account for each vehicle's scaled length.
  The bus width is normalized to 2.5 m and nominal person height to 1.75 m in
  the road's metric coordinate system; foot height follows a modeled 15 cm curb.
- The Hachiko frontage pairs the silver two-storey police box and its curved
  balcony with the taller JR entrance, recessed passage and clear roofline.
  The upper façade exposes its tiled cladding beneath the station name.
  The joined JR mark and serif station name have raised
  letter bodies. This compound is separate
  from the ribbed **JR 渋谷駅** rail bridge behind it. A6a, A6b and A7a have
  glazed Shibuchika pavilions, real stair wells, handrails and tactile landings;
  their full footprints and walking approaches remain clear of traffic and
  commuters. This geometry follows the city collapse/fade. See the
  [station and entrance contract](shibuya-architecture.md#station-frontage-and-subway-entrances).
  A four-car
  blue-striped metro crosses the east-side viaduct on a 14-second
  loop. Carriages have windows, doors, roof equipment, couplings, and end lights.
  Station portals conceal entry/exit clipping; the entire train leaves before
  its loop restarts. All moving geometry stays inside the city framing bounds.
  The interpreted metric dimensions are: 20 m cars at 20.8 m
  spacing, a track 7 m above pavement and an 8 m deck width. These are miniature design
  choices, not surveyed station or rolling-stock specifications.
- Activity freezes during the 3D/QR transformation and resumes on returning to
  settled 3D. QR view contains no city activity. Reduced motion uses one stable
  city pose; the player's existing pause and visibility lifecycle still apply.
- Animated geometry uses instanced meshes and reuses materials. Pedestrian
  parts share one draw call, and train details share one draw call.
  [`pedestrians.ts`](../../packages/designqr/src/designs/city/pedestrians.ts)
  plans both walking trips once and samples them during playback, independent
  of rendering frame rate. [`station-pedestrians.ts`](../../packages/designqr/src/designs/city/station-pedestrians.ts)
  connects selected curb positions to the modeled concourse. Its smaller plaza
  flow is also planned once, including local avoidance; paired commuters share
  a curb at different times without resetting visibly. A bounded CPU cache reuses plans when the content-derived population plan and
  building footprints match. [`traffic-cycle.ts`](../../packages/designqr/src/designs/city/traffic-cycle.ts)
  supplies the phase boundaries used by people, vehicles and signals.

## Billboards and configured logos

- Fourteen curated signs use six visual families: asymmetric crossing screens,
  light-ground fashion lettering, vertical karaoke/ramen signs, stacked tenant
  directories, café emblems, and horizontal lightboxes. Physical proportions
  follow the sign family and facade. Japanese shop lettering uses small original
  stroke glyphs so it does not require a host CJK font. All sign colors come
  from the shared morning material roles; there is no repeated universal frame.
- MAGNET has a tall corner poster, separate side poster and wider street-level
  screen. Western tenant signs use independent columns and rooftop boards.
  Panels follow crossing-facing source edges; rooftop boards have physical
  backs and supports for opposite-side orbit views.
- A loaded logo replaces the headline on the large front-facing billboard of
  QFRONT. The image fits without cropping or stretching;
  transparent pixels reveal the existing sign background. Its initial plane
  follows the angled building surface and uses depth testing when the city is viewed
  from other angles.
- One image plane travels from the billboard to the QR center during the turn,
  smoothly changing position, orientation, and size. The existing logo size
  bounds and high QR error correction remain authoritative for the scan face.
  Replacing or removing the logo restores/repaints the sign without retaining
  an old texture. Loading, validation, errors, pause, and export use the shared
  logo lifecycle. Tree logo behavior remains unchanged.

## City-to-QR transformation

City and Tree share one nominal transition duration (`5 / 9` seconds, about
0.56 seconds at 1×) and one easing curve. Both directions respond on the first
frame and settle smoothly. The editor and public `interaction.transitionSpeed`
divide that duration equally: 0.5× is about 1.11 seconds; 2× is about 0.28
seconds. Changing speed during a turn preserves its current elapsed proportion.
Reduced motion still commits directly to an endpoint.

The [whole-city morph](#whole-city-morph) uses a short coverage-first handoff,
not a long simultaneous alpha fade. The tile layer uses a fresh depth buffer
so the retiring facades cannot hide it; tiles still occlude one another.
Building sections, sign panels, crosswalk bands and street-life groups retain
their relationships before resolving into exact QR cells. Camera orientation
and the logo follow the same progress. This sequence is reversible and never
substitutes an unrelated QR image at the endpoint.

## Shared 3D sizing

Tree and City use the same `resolveQRViewportProjection().designDistance`
baseline: 2.45 in compact/square hosts, continuously approaching 2.85 in wide
landscape hosts. Both model footprint and camera distance scale with
`gridSize / 25`, so longer QR content does not enlarge the city. City has no
extra zoom. Its normalized tile occupies the same QR-relative world footprint
as Tree's terrace; their silhouette heights naturally differ.

The city retains its steeper overview angle and a geometry-bounds clipping
guard. The guard can only move the camera farther away; at the default angle
it adds less than 4% distance in narrow/square hosts. Rotation stays contained.
City's initial/reset yaw offsets Tree by −90°, looking north from the station
side toward the crossing-facing façades. It rotates the camera, not the map.
The 2D scan projection and editor-only 0.88 QR scale are unchanged.

Consumers size either design through the same `<DesignQR style={...}>` or
`className`, or the iframe's dimensions. Switching `design` requires no
City-specific scale correction, and does not change transition-speed semantics.

## Validation

Run package tests, public API type checks, production builds, lint, color/style
contracts, documentation checks, and production smoke checks. City verification
must cover 1440×900, 390×844, and 320×568 in both views; actual QR decoding;
share/embed round trips; visible-canvas/PNG pixel equality and exported QR
decoding; logo and transparency; reduced motion; and repeated
design switching. Check that different equal-size QR values visibly change the
skyline, restoring a value restores its reduced-motion frame, and denser values
keep the tile framing stable. Exercise generated plots across many values, including the rendered roof, awning, window, and sign geometry.
Verify default motion with camera rotation disabled, both commuter and metro
movement, continuous loops, curb clearance, and a frozen completed scan face.
Decode transparent borderless output over a host-owned light backdrop and
Border-enabled output over both light and dark backdrops. With Border off,
the four-module margin must stay transparent; with Border on it must be filled
with the same mist paper as light cells. Check the original PNG's alpha and
visible/export pixel equality separately.
Also cover natural sidewalk spacing/height, mixed vehicle queue clearance,
source-facing panel geometry, logo placement/replacement/removal, both transition
directions, and exact QR module positions after the handoff.
Sample every cell interior to verify the four data inks and deep-blue finders.
Check all four sides and corners of the margin for Border-owned fill, on both the visible canvas and
decoded PNG. Cover Border off, transparency and zero requested card padding. Exclude
antialiased edges and user-supplied logo pixels, not the surrounding QR cells.

The focused browser gate is `npm run smoke:designqr-city` (also part of
`npm run check`). Set `CHROME_BIN` when Chrome is outside the standard paths.
It uses port 4188 independently of the cross-origin iframe fixture;
`DESIGNQR_CITY_PORT` can override it.
For a focused rerun on a slow software-WebGL host, `DESIGNQR_CITY_EDITOR_WIDTHS`
can select comma-separated editor widths from the five defaults; an empty value
skips that initial viewport loop while retaining the player, live-content,
framing, logo, and remaining integration checks.
`npm run smoke:designqr-city-assets` covers model loading and responsive endpoints. `npm run check:designqr-city-package` installs a local tarball into
an isolated non-root-path consumer and checks lazy loading, errors, delayed
and stale completion, independent logos/disposal, resource counts, and PNG decode.

`npm run smoke:shibuya-content` exercises the real React-to-renderer update
path, checking actor/object identity and exact phase continuity, same-size and
57×57 content, repeated edits, paused/reduced-motion/mid-turn updates, logo
retention, QR export decoding and zoom-independent PNG bytes. It checks bounded
GPU allocations and disposal across edits, design changes and unmount.
The focused browser fixture uses port 4197 (`DESIGNQR_CONTENT_PORT` overrides
it); package unit tests additionally cover delayed model loading and exact new
QR destinations.

The layered-ink and Border regression checks cover both views at 1440×900,
390×844 and 320×568; short and dense matrices; Logo; transparent output; and
zero requested card padding. Pixel checks verify original matrix cells and
their selected inks, then verify that only Border fills the outer margin.
Automated decoding uses the appropriate host backdrop. Physical phone-camera
scanning remains a separate manual check.

## Local preparation

Use Node from `.nvmrc` and install the root lockfile with `npm ci`. The current
candidate is `0.1.0-rc.1`, with `publishConfig.tag` set to `next`. It has not been
published. Set the manifest and lockfile together; stable versions must use
`latest`, and prereleases must use `next`.

```sh
npm run release:pullground:check
npm run test:pullground-release
npm run pack:pullground
npm run check:pullground-package -- --tarball artifacts/pullground/johnson7543-pullground-0.1.0-rc.1.tgz
npm run check:pullground-package -- --tarball artifacts/pullground/johnson7543-pullground-0.1.0-rc.1.tgz --react-version 19.0.0 --online
```

Packing builds the workspace and retains the archive, file manifest, compressed
size, npm integrity, SHA-256, source commit, and dirty-tree marker under ignored
`artifacts/pullground/`. It does not publish. A successful consumer check retains
a report for its React version beside that archive. The isolated application is
removed afterward.

The consumer checker prefers npm's cache and downloads missing dependencies,
so it also works on a clean CI runner. Use `--offline` for cached-only checks or
`--online` to refresh registry metadata. `--react-version` changes React
and React DOM together in the temporary consumer, without changing the root
lockfile. Tests cover types, ESM/CJS, SSR, shared automatic CSS, hydration, and
mouse/touch/keyboard/action behavior. A supplied archive must match the current
release manifest and remain byte-for-byte unchanged through verification.

`npm run check` includes the release contract, its negative tests, and the packed
consumer test. It creates and validates a retained archive after building the
site. For the final candidate, run it from a clean checkout, then test that same
archive against React 19.0.0. The [release plan](release-plan.md) also requires
physical-device acceptance and updated media before publication.

## Workflow behavior

The [Publish Pullground workflow](../../.github/workflows/publish-pullground.yml)
supports two paths:

- `workflow_dispatch` runs verification and uploads evidence without publishing.
- A pushed `pullground-v*` tag runs the same gates and publishes only if the tag
  exactly matches the package version and its commit belongs to `main`.

It runs the full repository gate, checks the retained archive with the lowest
supported React, compares both consumer reports with its SHA-256, and retains
logs and artifacts for 30 days. The final step checks the archive hash again and
publishes that file, without repacking. Publication is serialized across the
workflow. The metadata guard rejects private packages, invalid versions,
incorrect channels, mismatched lockfiles/tags, and unexpected exports/files.

The runner uses the repository Node pin and npm 11.15.0 with GitHub OIDC. No npm
token is needed once the trusted publisher is configured. See
[npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) for the
supported runner, permissions, and repository requirements.

## First publication

First complete candidate acceptance and confirm the maintainer has publishing
access to `@johnson7543`. The planned bootstrap is a public `0.1.0-rc.1` on `next`,
using the accepted archive from a clean commit:

Before freezing that commit, replace the package README's unpublished banner
with a prerelease notice and retain its `@next` installation command. Repack and
qualify this final documentation with the archive; update the repository's
publication record only after registry verification succeeds.

```sh
npm login
```

Run the actual checksum and publication from the artifact directory, where the
checksum's relative filename resolves:

```sh
cd artifacts/pullground
sha256sum --check SHA256SUMS
npm publish ./johnson7543-pullground-0.1.0-rc.1.tgz --access public --tag next
```

Use account 2FA, then install the registry version into a fresh consumer and
verify it. Do not push a publishing tag for a manually published version; npm
versions cannot be reused.

Once the package exists and the stable candidate is ready, configure this npm
trusted publisher:

| Field | Value |
| --- | --- |
| Provider | GitHub Actions |
| Organization/user | `johnson7543` |
| Repository | `design` |
| Workflow filename | `publish-pullground.yml` |
| Environment | Empty |
| Allowed action | Direct `npm publish` |

The authenticated CLI equivalent is:

```sh
npm trust github @johnson7543/pullground --repo johnson7543/design --file publish-pullground.yml --allow-publish
```

`npm trust` requires an existing package, write access, and account 2FA. Create
the configuration close to publication: its first successful publish must
complete within two days. [npm trust documentation](https://docs.npmjs.com/cli/v11/commands/npm-trust/),
[trusted-publisher setup](https://docs.npmjs.com/trusted-publishers/)

## Stable release and website

Prepare `0.1.0` with `publishConfig.tag: latest`, synchronize the lockfile, update
the README installation/status text and [release notes](release-notes.md), and
review the final commit on `main`. Require the complete CI and device gates,
then exercise the verification-only workflow before pushing `pullground-v0.1.0`.

After npm publication, verify `latest`, provenance, exports, README, and a fresh
registry consumer. Deploy the website from the matching accepted commit, recording
the prior production deployment for recovery. Check `/`, `/pullground`,
`/refresh`, `/qr`, `/qr/embed`, preview media, and copied examples before announcing.
The existing `npm run deploy` targets production; it is not a staging command.

Restore the previous website deployment for a site regression. For a broken npm
version, validate a new patch version and deprecate the defective one when
appropriate. Keep the demo and package in sync; never overwrite a published
version or treat a local dirty-tree archive as the final accepted candidate.
